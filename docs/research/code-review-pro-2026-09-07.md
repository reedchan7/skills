# code-review-pro 改进与对照结果

版本约定：此前未标版本的旧版记为 **1.0.0**，本次改进版为 **1.0.1**。评测结束后在主文件 YAML frontmatter 中补充 `metadata.version: "1.0.1"`；原始评测快照与哈希保持原样。

本次确认的正向收益是：报告正文平均缩短 **31.6%**，独立可读性复核从 **7.5/8 提升至 8/8**；新增范围采集器通过 13 项真实 Git 行为测试。九项无歧义案例上的缺陷发现、合并建议和覆盖判断均无退步。

**没有测出更强的缺陷召回。** 三组在有效案例上全部达到评分上限，预先设定的“技术质量提升至少 20 个百分点或纠正至少两个独立失败场景”门槛未达到。本次按已证实的输出改进与范围可靠性改进收口，不据此宣称“100+”、通用审查能力显著提升或生产级召回率。

## 改了什么

- 严重度依据实际影响、可达条件和恢复成本；与分类、证据强度、合并建议分开。日志存在不自动降级，同一缺陷换分类不应改变合并建议。
- 收紧风险参考中的排除条件：同仓库不等于同时部署，有补偿/锁/outbox 不等于覆盖具体失败窗口；修正并发、SQL NULL、历史复发、客户端校验和 UI 状态的过宽规则。
- 按实际目标区分提交端点、merge base、index、工作区和未跟踪文件；采集内容与 index/context 漂移，显式暴露子模块等限制。
- 区分完成程度和合并结论；未知事项可能改变结论时表达“尚无法判断”，已确认阻塞问题仍然阻塞。
- 报告先给结论，再按根因列出定位、触发及影响、关键依据和最小建议；调查台账留在 scratch，去掉标签堆叠、重复裁决和无意义空节。

评测时主文件由 287 行减为 225 行；补充版本 metadata 后为 227 行。行数不作为质量评分。

## 试验设计与结果

独立案例作者未读取新旧 skill 或既有评测答案，创建 8 个可执行 Git 案例与 2 个材料综合任务。原始代码、任务及答案先冻结，随后执行三组各三次独立会话，共 90 份报告。每次拥有单独的输入副本；均未覆盖父模型与 effort 设置，工具可用范围一致，禁止网络、读取其他组输出与嵌套委派。

技术裁判在不知道匿名组对应版本的情况下核验因果与结论；另一个独立裁判固定抽取三组首轮全部 30 份报告，评价可读性。身份映射在下表公开，未提供给裁判。新旧 skill 内容在整个三轮过程中保持冻结。

| 指标 | 旧版 a16 | 无 skill m05 | 新版 z28 |
| --- | ---: | ---: | ---: |
| 已知 Git 根因检出，每轮 | 4/4 | 4/4 | 4/4 |
| 综合材料缺陷检出，每轮 | 1/1 | 1/1 | 1/1 |
| 有效案例误报，三轮合计 | 0 | 0 | 0 |
| 干净案例错误阻塞，三轮合计 | 0 | 0 | 0 |
| 重大漏报，三轮合计 | 0 | 0 | 0 |

| 每轮正文字符，最小–最大 | 5,330–5,841 | 4,016–4,635 | 3,717–3,864 |

正文字符统一去除 Markdown 链接目标、格式标记和空白，包含每轮全部十份报告；这是文本长度，不是模型 token、耗时或人类阅读时间。对应三轮新版相对旧版分别减少 30.3%、34.1%、30.2%。独立可读性裁判认为旧版五份首轮报告存在多重标签和重复阻塞裁决，新版全部保留必要条件及建议；无 skill 组与新版在该量表上持平。

技术裁判采用较粗的“可读且可行动”标准，三组均为 3/3；独立可读性裁判进一步检查冗余，得到 7.5/8 与 8/8 的差异。两种量表均原样保留，不能拿文本长度替代真实性评分。

## 必须保留的局限

1. **r074 事后排除主技术指标。** None 写回的行为可复现，但公开合同未定义 None 是清空还是保持。原答案也含未公开的 sentinel 意图。九份该案例报告均被一致排除，保留两种解释下的完整敏感性结果；不同解释会改变排序。主指标实际为每轮九项、共 81 份报告，不能冒充原十项未经调整的预注册结果。
2. 有效案例小且合同明确，产生评分上限。三次重复只衡量这组场景的稳定性，不是三个新的独立数据集；不能外推大型真实 PR 的精确率或召回率。
3. 各 reviewer 共享相同工具可用环境，但报告中使用的解释器有 Python 3.11 与 3.13；并非严格锁定的统一解释器试验。本批因果不依赖二者差异。没有采集可比较的 token 成本或端到端审查耗时。
4. 访问隔离通过独立输入与任务约束实现，未使用 OS 级文件/网络沙箱。未全面审计 reviewer 的全部执行日志；不把报告自述运行直接当作已审计履历。独立 custodian 已执行原始因果探针。
5. 材料综合任务中的浏览器记录是明确给定的合成证据，不是本轮真实浏览器验收。它们用于测量如何组织已有证据和表达未覆盖范围。
6. 本轮数据与答案归档公开后，只能作为已知回归集；后续能力评测需要新的隐藏案例。没有根据本批答案修改 skill。

## 范围采集器的独立复核

独立代码复核实际发现：`diff.ignoreSubmodules=all` 会使初版 helper 漏掉 gitlink 与本地子模块变更。公共 diff 调用现已显式使用 `--ignore-submodules=none`。

两项对应回归在修复前均失败，修复后完整 13 项测试通过。测试还覆盖提交端点与 merge base 的差异、staged/unstaged 抵消、未跟踪文件与特殊文件名、同状态字母下的内容漂移、index/context 漂移、重命名/删除/模式/软链接、初始无提交及合并冲突状态。采集器本身的测试确认未修改源文件、HEAD 或原始 index 字节。

九次评审涉及的 72 份 Git 仓库副本均保留了源文件内容、索引条目与 refs，且没有遗留注册的 scratch worktree。仓库副本完整性检查不等于全部执行命令的审计。

## 安装状态

已同步到本机 `~/.agents/skills/code-review-pro`，Codex 的现有链接继续指向该安装目录。主文件除安装名和评测后补充的版本 metadata 外与三轮评测的冻结版本一致，references 与新 scripts 均解析到当前仓库。安装目录的 skill 校验通过；从实际安装入口运行范围采集与 recheck，返回 unchanged=true、退出码 0。归档解压到新的临时目录后，两组独立因果探针也重跑通过。
