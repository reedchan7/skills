# Refactor skill 1.0.1：设计依据与评测记录

本次目标是提高重构的判断与结果质量：识别维护障碍、选择合适的结构、
保留行为，并用后续理解或修改任务检验收益。旧版未声明版本，本记录以
原始内容哈希识别旧版；不追溯编造其版本号。

## 从来源到决策

本轮核对了作者、出版社、大学、研究机构及官方项目的一手材料。
完整链接、阅读范围、证据类型与局限保存在
[sources.md](../../skills/refactor/references/sources.md)。未声称完整阅读仅提供
目录、摘要或样章的书籍与论文。

- Fowler 与 Feathers：小步行为保留、具体修改动机、现有行为观察与最小测试接缝。
- Parnas 与 Ousterhout：按隐藏的设计决策划分责任，观察调用者需要知道什么，
  避免用浅层拆分增加理解与导航负担。
- Beck、GoF 与 Sandi Metz：比较直接实现与模式的收益/代价，允许内联、合并、
  拆回错误抽象；重复次数和模式名称不能单独决定方案。
- Liskov/Wing：实现替换需要保留调用者保证，签名一致不足以证明替换安全。
- McCabe/NIST 与 Sonar：区分控制流与认知复杂度；保持工具、范围与口径一致，
  追踪提取后的逻辑，防止通过拆函数或搬分支制造指标改善。
- Tornhill：以变更耦合补充静态依赖，同时考虑批量提交、样本量与工作流混杂。
- Saltzer/Schroeder 与 OWASP：在受影响的边界追踪授权、身份、失败、敏感数据
  和资源约束；安全能力服务于具体重构，不擅自扩大为全仓安全改造。
- Microsoft 实证研究与质量映射研究：收益需要分维度观察，不从行数、绿灯
  或经典原则直接推导出缺陷率、生产力提升。

上述材料被综合成决策问题与按需参考，没有把作者观点逐条堆成普遍硬规则。

## 实现变化

- 区分评估、计划与执行；局部重构不再依赖 RT 文件，系统性执行不会以产出计划
  代替完成用户请求。继续已有授权，重要的真实取舍才需要决定。
- 增加问题假设、反证、最小方案与收益证据；提取/内联、拆分/合并、引入/移除
  抽象都可成为候选。
- 增加质量参考，覆盖内聚、信息隐藏、变更局部性、理解负担、复杂度、测试接缝、
  安全可靠性、性能与交付成本。选定主收益与相关约束，不要求所有维度满分。
- 修复旧版回滚示例、打印凭据、Tidy 新增配置行为等风险；按实际工作内容识别
  基线和归属，只撤销本轮改动。
- 收紧快照归一化与测试变更，补充状态、异步、事务、取消、动态引用等变换风险。
- 更新独立 RT 协议为 v2，并保持旧任务在当前授权与安全约束下可按实质合同执行。
- 报告侧重实际责任变化、行为和收益证据，明确区分测得、静态支持与尚未知。

主入口保持 153 行，字节数由 8,349 增至 9,072。全部 Markdown 资源从 9 份、
38,263 字节增加到 12 份、59,647 字节；新增深度有上下文成本，按需加载用于限制
普通任务的负担。行数与字节数不是质量或模型 token 指标。

独立案例作者未读取新旧 skill，创建六个公开合同清晰的本地 Python 仓库，
覆盖发票输出、运费决策、凭据轮换、已有工作区修改、局部规范化和独立金额政策。
公开/私有行为检查均在原始仓库通过，六个故障变体均被检出。

候选、输入、私有检查与量表在执行前冻结。三组各两轮，共 36 份真实代码结果；
另有两个未提前披露的维护需求，交给新的执行者在各组结果上实施，共 12 份。
裁判不接收组别映射，行为、实用性和结构质量分别评定。

具体预设门槛见 [eval README](../../evals/refactor/README.md)。未达到门槛时如实
区分指令修复与未证实的行为质量跃迁，不事后降低门槛。

## 已证实的改进与适用限制

三个隔离反例确认旧指令中的具体风险：旧凭据搜索命令会输出测试凭据，新命令
只输出文件位置；旧整文件恢复示例会抹掉初始改动，按本轮改动恢复能同时保留
初始与后续修改；Tidy 把常量接到配置后，在覆盖值存在时会改变有效行为。
这些支持指令修复，不能替代 Agent 在更多未知案例上的行为证据。

新增设计判断、质量、安全参考和执行路由已经实现，来源阅读范围已逐项标明。
普通局部请求可直接执行；大型任务以可运行的纵向切片推进，并用具体维护问题
判断是否继续。测试全绿、拆函数、降低单函数复杂度不再足以支持收益结论。

本轮的外推范围有限：

- 六个本地 Python 单模块合成仓库，不代表真实多模块迁移、UI、并发状态、
  数据库事务或生产安全完整性。Python 3.8 仅做语法兼容观察，未运行该版本。
- 每组每轮一个新 Agent 顺序处理六个案例；重复执行不是新增独立数据集。
  使用相同继承模型设置和工具权限，未测量模型 token、人工时间或生产力。
- 执行采用独立目录与访问指令隔离，没有操作系统沙箱；最终树可确认内容和
  index/refs，不足以完整证明过程中的所有外部行为。
- 一次后续需求仅说明该需求的修改范围。维护结果同时受起始结构与新执行者影响。
- 全部参考资料增加约 56% 字节，主入口增加约 8.7% 字节。按需加载减少常规
  任务负担，但本轮没有测得实际上下文或耗时收益。

下一轮若要检验质量跃迁，应在真实维护障碍明确的多模块材料上，先冻结任务、
相同边界的基线、后续需求与评价尺度，再做比较。已公开案例保留为回归材料，
不能再次作为未知案例证据。
